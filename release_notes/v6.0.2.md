# Kerykeion 6.0.2

Release date: 2026-09-16 · Security maintenance release · Python 3.12+

This patch resolves two moderate dependency vulnerabilities reported by
Dependabot. Both `kerykeion` and `kerykeion-cli` use version `6.0.2`; the CLI
continues to pin the library at the exact same version.

## Security fixes

- Update the transitive runtime dependency **idna** from 3.11 to 3.16, fixing
  [GHSA-65pc-fj4g-8rjx](https://github.com/advisories/GHSA-65pc-fj4g-8rjx) /
  CVE-2026-45409. Versions before 3.15 can spend excessive resources on
  specially crafted input passed to `idna.encode()`, causing denial of service.
  Kerykeion's direct network path uses the fixed GeoNames hostname, which limits
  practical exposure, but the vulnerable package is no longer present in the
  resolved runtime graph.
- Update the development dependency **pytest** from 9.0.2 to 9.0.3, fixing
  [GHSA-6w46-j5rx-g56g](https://github.com/advisories/GHSA-6w46-j5rx-g56g) /
  CVE-2025-71176. Earlier releases use an insecure predictable temporary
  directory on UNIX. The declared development floor is now `pytest>=9.0.3`, so
  future lockfile resolutions cannot restore an affected version.
- Update **url-normalize** from 2.2.1 to 3.0.0 alongside `idna`. This removes its
  call to the deprecated `idna.encode(..., transitional=True)` API while
  remaining compatible with Kerykeion's Python 3.12+ requirement.
- Update the transitive runtime dependency **Click** from 8.3.1 to 8.3.3 after
  the release audit identified
  [GHSA-47fr-3ffg-hgmw](https://github.com/advisories/GHSA-47fr-3ffg-hgmw) /
  CVE-2026-7246, a reported command-injection issue in `click.edit()`. Kerykeion
  does not call that function and the Click project disputes the CVE, but the
  prepared dependency graph no longer contains a reported affected version.

The dependency update also exposed an order-dependent CLI test: the in-process
runner reset `--traceback` and `--warnings-as-errors` state, but not
`--envelope`. The fixture now resets all three process-global policies before
and after each test.

## Compatibility and installation

There are **no public API, calculation, rendering or CLI behavior changes** from
the previous stable v6 release. The default backend remains
`libephemeris==3.2.1`, Python 3.12+ is still
required, and a plain library install still provides no shell command.
Installation examples are intentionally unpinned so the maintained docs always
select the latest stable release; exact version identifiers remain only where
needed to record release history or identify publication artifacts.

```bash
# Python library
pip install --upgrade "kerykeion"

# Library and CLI
pip install --upgrade "kerykeion[cli]"

# Isolated CLI installation (replace an existing uv tool installation)
uv tool install --force "kerykeion-cli"
```

For upgrades from v4 or v5, read the
[migration guide](https://www.kerykeion.net/content/docs/migration) and
[6.0.0 release notes](https://github.com/g-battaglia/kerykeion/blob/main/release_notes/v6.0.0.md).

## Maintainer publication checklist

Build both distributions into `dist/6.0.2/`. Keep older artifacts separate.
Verify the prepared files from the repository root:

```bash
shasum -a 256 -c dist/6.0.2.sha256
```

Review the release commit and annotated tag `v6.0.2`, then push them when ready.
Publish the library first:

```bash
uv publish dist/6.0.2/kerykeion-6.0.2-py3-none-any.whl dist/6.0.2/kerykeion-6.0.2.tar.gz
```

Once the library is visible on PyPI, publish the CLI:

```bash
uv publish dist/6.0.2/kerykeion_cli-6.0.2-py3-none-any.whl dist/6.0.2/kerykeion_cli-6.0.2.tar.gz
```

Verify the published packages in a fresh environment:

```bash
uv run --isolated --no-project --with "kerykeion[cli]" kerykeion --version
uv run --isolated --no-project --with "kerykeion[cli]" kerykeion status --check -f json
```

Use these notes for a normal GitHub release, not a pre-release. Preparation does
not publish packages, push the tag or create a GitHub release.
