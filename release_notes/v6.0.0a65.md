# v6.0.0a65

This alpha lands rounds 36–47 of the zero-bug review campaign: twelve further
review rounds, each rotating a fresh runtime-reproduced lens and adversarially
re-reviewing the previous round's own diff. Rounds 45, 46 and 47 closed with
zero findings. Every fix was reproduced by execution before being applied and is
covered by a regression test.

## Golden baselines regenerated on the pinned engine

`6.0.0a63` regenerated the baselines with libephemeris `3.0.0rc1` while the same
commit pinned `==3.0.0rc3`, whose upstream speed-model fixes shift speeds by
~1e-4 °/day — enough to fail 58 tests on tolerance and flip near-threshold
aspect-movement labels in the report snapshots. All expected-position, aspect
and subject data and the report fixtures were regenerated on rc3 at the
`extended` (DE441) tier, which also restored the previously unregenerable
`natal_ancient_rome` fixture.

## Silent-drop and contract fixes

- **BCE event splitting.** `TransitsTimeRangeFactory` computed sampling gaps with
  `datetime.fromisoformat`, which raises on extended-year ISO strings; the
  `except` mapped that to "gap 0", silently merging every recurrence of an aspect
  in a BCE range into a single event. Both call sites now use BCE-safe day
  arithmetic.
- **Pre-1 CE progression window.** A progressed Julian Day landing in the ~2-day
  window before 1 CE decomposed to Julian year 1, which `from_birth_data`
  reinterpreted as Gregorian, building the progressed chart two days late; it is
  now clamped with a warning.
- **Civil-range edges.** `pytz.localize` probes the surrounding day, so the first
  and last civil days crashed with a raw `OverflowError` in `SunTimesFactory`,
  `PlanetaryHoursFactory` and `VoidOfCourseMoonFactory` instead of the documented
  `KerykeionException`.
- **Transits to non-default points.** `EphemerisDataFactory` accepted no
  `active_points`, so transits to asteroids/TNOs silently produced zero events;
  it now forwards an optional `active_points` list and warns when a requested
  point is missing from the natal or ephemeris side.
- **Sect (`is_diurnal`) lost at the model boundary.** The value was computed by
  the return and Davison factories but dropped by pydantic (undeclared field), so
  sect-aware consumers treated every night return as a day chart. Both models now
  declare `is_diurnal`.
- **`active_points` contract.** Unknown names (a typo such as `"Sunn"`) were
  silently dropped and an explicit empty list inverted into a full default chart;
  both now raise `KerykeionException`. Geocentric-only points requested in a
  non-geocentric chart now warn (or raise, if that leaves the chart empty), and
  the `Interpolated_Perigee` (`SE_INTP_PERG`) phantom is excluded like the other
  geocentric-only points.
- **Zodiacal releasing and fixed-star discovery on returns/composites.**
  Zodiacal releasing's `from_subject` and `find_prominent_stars` crashed or
  silently returned `[]` on `PlanetReturnModel` / `CompositeSubjectModel`; both
  now anchor on the ISO timestamp or raise a clear `KerykeionException`.
- **Nakshatra pada boundaries.** The pada was computed from the remainder against
  the span constant, so exactly representable boundaries landed in the previous
  pada; both nakshatra and pada now derive from a single 108-quarter index.

## Swiss Ephemeris suite and documentation

The Swiss Ephemeris backend suite was restored to green — the failures were
test-side, not backend defects (the backend holds sub-arcsecond parity with
libephemeris). The pass also applied ~140 verified documentation corrections
across `site/docs`, `site/examples`, `README.md` and `kerykeion/llms.txt`, with
every snippet re-executed and its real output pasted in; the snippet harness
itself was rehabilitated after it was found to produce ~16% false passes.
