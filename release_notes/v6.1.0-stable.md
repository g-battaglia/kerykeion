# Kerykeion and CLI 6.1.0 — stable preparation

This is the current stable preparation from the qualified b5 implementation,
including subsequent README-only maintenance. It is not the earlier b1-based
[archived stable draft](v6.1.0.md), and that draft's validation counts and
artifact checksums are not evidence for these files.

Both distributions use `6.1.0`; the CLI requires exactly `kerykeion==6.1.0` and
the library requires exactly `libephemeris==4.0.0`. Both use the stable
classifier. Source preparation, a source tag and local archives do not establish
PyPI publication.

## Scope and compatibility

The promotion preserves the current b5 numerical implementation, SVG resources,
scientific references, producer manifests and numerical tolerances. Installation
messages, package versions, documentation and the generated man page follow the
stable identities. A targeted security follow-up advances only the HTTP-stack
packages `certifi` and `urllib3`; the other 52 external lock records retain their
qualified identities, and the native backend remains exactly `4.0.0`.

The native stable source retains the b4 numerical core and coefficient bytes.
Reusing the original native model references requires a separate, version-exact
source-identity qualification: neither a stable label nor a matching major
version permits reuse for an unknown backend. Reference generation remains
restricted to the original producer.

The changes accumulated during the beta series remain described in the
[changelog](../CHANGELOG.md): native v4 sessions and shared coverage metadata,
resource/path ownership, inclusive horizon classification, opt-in SVG provenance
notes and relationship scoring v2. Existing scoring v1 remains the default;
`reference_verified=false` remains unchanged for v2 scoring metadata.

Historical angles, houses and derived outputs can differ from the v3 backend.
The [scientific compatibility notes](v6.1.0b1.md#scientific-compatibility) and
[migration guide](../site/docs/migration.md) describe that distinction. A small
bundled core is not full body/date coverage; wider datasets remain explicit
prerequisites. Historical performance measurements retain their original
versions and scope; no new performance claim is made by this promotion.

versions and a separately installed native stable candidate: `poe check`,

passed (three intentionally non-runnable CLI blocks remain skipped).

The extended source suite passed 14,798 cases on Python 3.12 and 14,799 on

interpreter without changing reference bytes or tolerances. Thirteen Swiss-only

font check reproduced its shipped block using checksum-verified existing fonts,

`84b70895124c5e5685df3c44a389f230a7fa6102`. The initial stable registry lock
updated only Kerykeion, CLI and LibEphemeris; its 54 unrelated package records
were unchanged before the targeted HTTP security follow-up below.
The initial registry-backed source rerun passed `poe check`, documentation

## Targeted HTTP security follow-up

A subsequent advisory review identified affected locked versions of `certifi`
(`2026.1.4`) and `urllib3` (`2.7.0`). The release requires
`certifi>=2026.10.18` and `urllib3>=2.8.0`, with those patched versions selected
in the lock. These explicit runtime floors also protect existing installations;
updating a development lock alone would not force an already-satisfied Requests
installation to upgrade its transitive dependencies.

This addresses the declared ranges in
[GHSA-6q48-6c7w-9gw2](https://github.com/advisories/GHSA-6q48-6c7w-9gw2),
[GHSA-vxq7-64xx-v4gw](https://github.com/advisories/GHSA-vxq7-64xx-v4gw),
[GHSA-8988-9cw3-xx77](https://github.com/advisories/GHSA-8988-9cw3-xx77), and
[GHSA-gh4c-6fx4-qh6g](https://github.com/advisories/GHSA-gh4c-6fx4-qh6g).
It is not a general security audit or a claim about unknown future advisories.
No other package is upgraded and no numerical reference or tolerance changes.
The final security-lock rerun passed `poe check`, documentation coverage,
423 Python snippets, and all 39 runnable CLI skill blocks. Python 3.12 and
3.14 each passed 14,801 extended cases plus all 13 medium-only cases, covering
14,814 distinct native cases per interpreter. The 27 extended skips retain the
same explicit classification above, and three online cases remain deselected.
Two new installed-metadata regressions ensure an affected existing HTTP package
cannot satisfy the published dependency requirements.

A fresh-HOME, sealed bundled-base consumer also passed library-only rendering,
CLI status/version and installed man-page checks with the patched HTTP versions
and LibEphemeris installed from PyPI. Earlier counts above identify the
pre-security cohort; final archive verification remains separately required.

## Archive verification

A precommit clean-room installation also passed the offline library-alone
render with no CLI command, followed by the separately installed CLI, version,
backend diagnostics and materialized/rendered stable man page. It used a fresh
HOME, sealed network policy and only the bundled base image.

Final archives must be built from the clean, pushed release commit and checked
separately: strict metadata/licenses, independent offline sdist rebuilds and
isolated Python 3.12/3.14 library/CLI installs. Their checksum/provenance record,
not an earlier draft or precommit archive, identifies the upload files. These
source notes do not establish that Kerykeion or its CLI is already on PyPI.

## Maintainer publication checklist

1. Verify LibEphemeris 4.0.0 and its immutable official file hashes on PyPI.
2. Resolve the final public lock, preserving unrelated dependency records, and
   complete the final tests from the reviewed source revision.
3. Build and verify four archives from that revision: wheel and sdist for the
   library, then wheel and sdist for the CLI. Record exact source and SHA-256
   provenance in a version-specific output directory.
4. Freeze a new immutable source tag only after the required checks pass.
5. The maintainer publishes only the two verified library archives with
   `uv publish`; verify library visibility before publishing the two CLI archives.

Preparation does not run either upload. Do not select an unqualified general
`dist/` directory, rebuild an already published file, move an earlier tag, or
substitute the archived stable draft's files. A partial upload resumes with the
same verified archives, not a rebuilt package.
