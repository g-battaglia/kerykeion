# v6.0.0a59

This alpha changes the Moon-phase sun-timing fields to native date/time types
and extends the axis orb limit to dual charts, plus a follow-up review pass.

## `MoonPhaseSunInfoModel` sun-timing fields are now native types

`sunrise` and `sunset` change from an integer epoch timestamp to a
timezone-aware `datetime`; `solar_noon` changes from `str` to `datetime`; and
`day_length` changes from `str` to `timedelta`. The two convenience string
fields `sunrise_timestamp` and `sunset_timestamp` (previously `"HH:MM"`) are
removed with no alias, so the serialized JSON shape changes to ISO-8601
datetimes and duration. Derive the old `"HH:MM"` value via
`sun.sunrise.strftime("%H:%M")`. A validator now rejects naive `datetime`
values; the field annotations are unchanged, so `get_type_hints()` on the public
API is unaffected.

## `axis_orb_limit` now filters dual-chart aspects

Previously the axis-specific orb limit applied to single-chart aspects only and
was a documented no-op for synastry, transit and composite charts. It is now
applied uniformly: a non-`None` `axis_orb_limit` passed to
`AspectsFactory.dual_chart_aspects` (and through `TransitsTimeRangeFactory` and
`RelationshipScoreFactory`) keeps an axis aspect only when its orb is below the
limit. The default remains `None` (no axis filtering).

## Review follow-up (PR #224)

- The `house_position` chart label shipped with the `natal_house` value ("Natal
  House") in all 10 languages; it now renders the distinct "House Position"
  label, and the affected English golden SVG fixtures were updated.
- `MoonPhaseSunInfoModel.solar_noon` could carry the wrong local offset on
  DST-transition days; the midpoint is now normalized back through the timezone.
- `format_timedelta_hhmm` used banker's rounding on exact half-minute durations;
  it now rounds half-up.
- `AspectsFactory` axis filtering rejects a non-positive `axis_orb_limit` with
  `ValueError` instead of silently dropping every axis aspect.
