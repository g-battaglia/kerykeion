# v6.0.0a52

This alpha adds a lunation-calendar finder and enriches eclipse search with the
luminary's zodiac position plus Saros/Inex/gamma/duration metadata. It also
raises the `libephemeris` floor to `2.0.2`.

## Lunation finder

`LunationFinderFactory` (`kerykeion.lunations`) finds New Moon, First Quarter,
Full Moon and Last Quarter across a date or Julian-Day range (`from_iso_range` /
`from_julian_day`). It drives `compute_lunar_phase_jd`, iterating each phase
independently at a half-synodic step so the binary-search solver never
degenerates on adjacent phases. The result is a `LunationsCollectionModel` whose
items carry the phase name, UTC timestamp, Julian Day and the Sun/Moon
`KerykeionPointModel`. `LunationFinderFactory`, `LunationModel` and
`LunationsCollectionModel` are re-exported from the package root.

## Eclipse zodiac and physical metadata

`SolarEclipseModel` and `LunarEclipseModel` gain optional `ecliptic_longitude`,
`sign`, `sign_num` and `degree` of the luminary at maximum, plus `saros` and
`inex` (and, for solar eclipses, `gamma` and `duration_minutes`). The values
come from the libephemeris extensions and are guarded with `hasattr`, so they
are `None` on the swisseph backend. The change is additive and backward
compatible.

## Dependency

`libephemeris` is pinned to `==2.0.2`, which fixes global lunar-occultation
search under the `extended` (DE441) precision tier: `lun_occult_when_glob`
previously clamped post-1969 searches to the DE441 segment split and returned no
events.
