# v6.0.0a85 — The whole library, from the terminal

This alpha adds an **optional** command-line interface. **No calculation changed,
and no public name moved:** `kerykeion.__all__` is exactly what a84 exported,
every Pydantic schema is byte-identical, and `import kerykeion` is unchanged. The
CLI is an `extra` — `pip install kerykeion` without it behaves exactly as before.

## `kerykeion[cli]`

A new optional extra exposes the entire library from the terminal, without
writing any Python:

```
pip3 install "kerykeion[cli]"
```

It is a **local** engine: it computes with the same in-process backend as the
library (libephemeris by default, Swiss Ephemeris when installed), so it works
offline and needs no API key. It is backend-agnostic — every command produces the
same output on either backend, exactly as the library does.

### What you can do

- **Charts:** `natal`, `synastry`, `transit`, `composite`, `return`,
  `progression`, and `now` (the current moment).
- **Analytical techniques:** `technique` groups profections, firdaria, zodiacal
  releasing, mutual receptions, horary, midpoints, directions, astro-cartography,
  fixed stars and relocation.
- **Sky events:** `sky` groups eclipses, lunations, sign ingresses, retrograde
  stations, mundane aspects, planetary phenomena, nodes, sun times, planetary
  hours and void-of-course moon.
- **Time series:** `ephemeris` and `transits` sample positions over a range.
- **Subject profiles:** `subject save|show|list|path|verify` — save a birth-data
  recipe once (`0600`, because birth data is PII) and reuse it everywhere with
  `-s <name>`.
- **`call`:** a guarded dispatcher that reaches any public `Factory.method` (or
  bare function) in `kerykeion.__all__` without a dedicated command.

### Output discipline

The output format is chosen for you: **text on a TTY, JSON in a pipe**. So
`kerykeion natal -s ada` reads as a report, while
`kerykeion natal -s ada | jq -r .sun.sign` works with no extra flag. `-f` forces
`text|json|xml|svg`; `-o file` infers the format from the suffix.

Two invariants hold everywhere:

1. **Payloads go to stdout, warnings go to stderr.** A payload piped to `jq` is
   never corrupted by an ephemeris-coverage notice, even under `-f json`.
   `--warnings-as-errors` turns them into exit `9` *after* the payload prints.
2. **No `rich.Console.print` on stdout.** Rich would wrap a fixed-width report
   and inject ANSI into a piped JSON. Rich is used only for chrome (help, error
   panels), on stderr.

### Clean errors, never a traceback

Every error is one line on stderr with the right code, never a traceback (use
`--traceback` to see one):

| Code | Meaning |
|------|---------|
| `0` | success |
| `1` | unexpected error |
| `2` | usage error (Click/Typer) |
| `3` | a full-CLI subcommand needs the `[cli]` extra (the base command — `status`, `--version`, `--help` — works without it) |
| `4` | invalid input |
| `5` | a `KerykeionException` |
| `6` | an ephemeris / backend error |
| `7` | a network error |
| `8` | sampling limit exceeded |
| `9` | warnings treated as errors |
| `130` | interrupted |

## The import invariant, and a useful command without the extra

`import kerykeion` stays free of `typer`. The `kerykeion` command is installed
even by a plain `pip install kerykeion` (the console script is static metadata),
so the no-extra path is the default for users who do not read the docs. Rather
than a dead end, the bare command is **useful out of the box** through a
stdlib-only core that needs no `typer`/`rich`:

- `kerykeion status` prints the runtime state — active backend (libephemeris or
  Swiss Ephemeris) and its version, the LEB calc mode, the precision tier and
  network policy, the LEB data files (paths, sizes, year coverage, body count),
  whether pyswisseph is available, and the `KERYKEION_*` / `LIBEPHEMERIS_*`
  environment knobs in effect. `--json` emits the same as machine-readable JSON.
- `kerykeion --version` / `-V` and `kerykeion --help` / `-h` (and a bare
  `kerykeion`) exit `0`.

`--version` and `--help` do not even import `kerykeion` (the version is read
via `importlib.metadata`), so they return instantly; only `status` pays the
backend init, and it does so to report real state. Any *other* subcommand
(`natal`, `transit`, …) prints a one-line install hint and exits `3` — never a
`Traceback`.

This is enforced in three places: `kerykeion/cli/__init__.py` imports `typer`
only lazily inside `main()`; `kerykeion/__init__.py` never imports `kerykeion.cli`
(it is untouched); and `tests/core/test_public_api_surface.py` excludes
`kerykeion.cli` from its `walk_packages` import sweep. A dedicated test asserts
that `import kerykeion` leaves `typer` out of `sys.modules`, and a subprocess
test drives the no-extra dispatch by blocking `typer`/`rich` on `sys.meta_path`.

## Security is an allowlist

`kerykeion call` reaches any name in `kerykeion.__all__`, split on a single `.`,
with no private members and no activated descriptors. `kerykeion call os.system`
is refused — `os` is not in `__all__`:

```
$ kerykeion call os.system --param cmd=ls
kerykeion: error: 'os' is not in the kerykeion public API; ...
```

That refusal is an explicit test, not a hope.

## Testing for identity, not snapshots

`tests/core/test_cli.py` asserts that a command's payload **equals the library
model built from the same inputs** — `json.loads(stdout) ==
json.loads(model.model_dump_json())` — never a golden file. An identity test is
immune to ephemeris drift: if the Sun moves, both sides move together. There is
deliberately **no** `regenerate:cli` task. The suite carries the `cli` marker
(`poe test:cli`) and runs in-process via `typer.testing.CliRunner`.

## Dependencies and licensing

The extra adds `typer` and `rich` — both **MIT**. No Apache-2.0 dependency was
added (the repo's standing rule); `NOTICE` carries a new "Optional command-line
interface" block listing every transitive license (typer, rich, shellingham ISC,
annotated-doc, markdown-it-py, mdurl, pygments BSD-2, colorama BSD-3; Click is
vendored by Typer under its MIT, not listed separately).

`typer` and `rich` are declared in **both** the `[cli]` extra and the `[dev]`
group. This is intentional, not redundancy: `pyrightconfig.json` runs in `basic`
mode where `reportMissingImports` is an error across the whole `kerykeion/` tree,
so without them in the dev environment every contributor's `poe typecheck` fails
on `kerykeion/cli/`. The extra is what a user installs; the dev group is what a
contributor needs to type-check.

The local-gates-only policy is unchanged: no CI was added, and
`.github/workflows/` stays empty. The CLI ships two new local tasks —
`poe test:cli` and `poe cli:smoke` — and `poe build:smoke` grew a third isolated
environment that verifies the no-extra degradation (the command exists, exits
non-zero with the install hint, and prints no traceback).

## Hardened after a review pass

Before merge the CLI was put through a code review that verified each finding
against the live interpreter. Every silent-wrong-output and exit-code path it
reached was closed (the CHANGELOG carries the full list); the headline fixes:

- **A date-only natal is no longer silently non-deterministic.** `natal` without
  `--time` now requires it (exit 4) — the factory was filling the birth time from
  the wall clock, so two runs a minute apart produced different charts.
- **`--no-online` / `--offline` actually stay offline**, overriding a profile
  saved with `online=True`, and apply to the natal half of a transit/return dual
  wheel — not just the transit moment.
- **`--set` validates against the recipe shape**, not the raw factory signature,
  so factory-only keys (`year`, `hour`, `suppress_geonames_warning`, …) are
  rejected instead of colliding in `materialize` or breaking `subject save`.
- **The ephemeris pre-flight count is DST-aware** (UTC for hours/minutes), so it
  matches the library's own ceiling check across a DST boundary instead of
  under-counting and letting an over-ceiling series slip to the wrong exit code.
- **Every bad path reaches the right exit code** — `-o` on a directory, `--step 0`,
  `--year 0`, `--time 24:00`, `transit --to-time` without `--to-date`, a typoed
  `call --param`, and a `typer.Exit` through the boundary are all the intended
  clean code (mostly exit 4), never exit 1 with a traceback.

A **second** review pass (same method: every candidate verified against the live
interpreter) closed a further round of gaps, with one regression test per fix:

- `call -s` now binds a `Union`-typed subject parameter (`AstrologicalSubjectModel |
  CompositeSubjectModel | PlanetReturnModel`, as on every `AspectsFactory` method),
  which `_is_subject` had misclassified — so the whole aspects surface was
  unreachable through `call -s`.
- `transit -s <profile>` defaults the transit moment to the **natal birthplace**
  (offline) instead of going online with an empty GeoNames query; `--to-date`
  without `--to-time` is a clean exit 4 (not a misleading "use `kerykeion now`").
- `--set active_points=sun,moon` coerces to a list (it stored a string the recipe
  then rejected); `sky eclipses` with only one of `--lat`/`--lng` is rejected
  rather than silently running a global search.
- `call --list` no longer advertises Pydantic-model methods it cannot dispatch;
  `--warnings-as-errors` is honoured even when the renderer itself crashes.
- `-o` files and saved profiles are UTF-8 with **LF** endings on every platform
  (no cp1252 `UnicodeEncodeError`, no CRLF corruption of JSON/SVG), and
  `created_at` is UTC-aware.
- libephemeris coverage/data errors map to exit 6 (not 5/4); `transits` surfaces
  a missing profile as exit 4 instead of swallowing it; `main(argv)` honours an
  explicit `argv` on the Typer path too.

Three findings were deliberately left out of this pass: `**kwargs` dispatch in
`call` (no public method currently has one — the guard already fails safe);
Click in the base `NOTICE` (pre-existing, unrelated to this feature); and gating
`test:core` on the `[cli]` extra (the dev workflow always installs it, and an
`importorskip` would hide regressions — a stated principle of this suite).

A **third** review pass (same method) closed a further round, again with one
regression test per fix. The two highest-severity items were silent wrong-output
bugs in the hand-maintained house-system name map, caught by cross-referencing
it against the library's `HousesSystemIdentifier` Literal:

- **`--houses porphyry` no longer silently builds Alcabitius.** The map coded
  Porphyry as `"B"` (Alcabitius); the correct code is `"O"`. **`--houses apc`
  no longer always fails:** it was coded `"n"`, which is not even a member of
  the Literal (APC is `"Y"`). An unknown single letter (`G`, `J`, …) is now
  rejected at the flag with a clear "unknown house-system letter" message
  instead of a confusing pydantic literal error from the factory.
- **`technique directions` no longer advertises a `--planets` flag that always
  crashed.** Primary directions have no planet filter; the flag was bound to the
  factory's `aspects` parameter (which takes *angles*), so any value raised. It
  is now `--aspects`, validated against the real aspect angles.
- **The transit wheel now shares the natal frame.** `transit` carried only the
  coordinates into the transit subject, so the outer ring was always
  Tropical/Placidus regardless of a Sidereal natal; `create_transit_chart_data`
  does not re-frame, so both rings must be built in the same zodiac.
- **An offset-bearing `sky --from` is honoured.** `sky voc|hours|sun-times`
  extracted the raw year/month/day/hour/minute from `--from` and re-read them in
  `--tz`, so `--from …T12:30:00Z --tz Europe/Rome` shifted the moment by two
  hours; an offset-aware instant is now converted into `--tz` first.
- **`--refine` without `--events` is rejected** (it only sharpens events and was
  a silent no-op otherwise); **a typoed `call Factory.method` is exit 4**, not
  exit 1 with a traceback (a missing member raised `AttributeError`, which
  `classify` did not list); **a dict `--param` is parsed as JSON** (it was
  forwarded as a literal string, so `custom_weights='{"sun":1.5}'` could never
  reach the factory).
- **Warnings reach the right stream and the right commands.** `emit_warnings`
  now resolves `sys.stderr` at call time (the default arg bound it at import, so
  CliRunner/capsys redirection missed it); `subject show|list|verify` route
  through the unified warnings funnel, and `verify` collects warnings from the
  materialised subject (not the compact summary it prints), so
  `--warnings-as-errors` engages there too.
- **`-o` into a new directory works** (the parent is created, matching
  `subject save`); **a `-s` lookup miss no longer creates the profile store** as
  a side effect of gathering suggestions; and the CLI's `--traceback` /
  `--warnings-as-errors` knobs are reset between in-process test runs (an
  autouse fixture) so the suite is no longer order-dependent.

Two findings were deliberately left out of this pass: the sampling pre-flight's
off-by-one across a DST boundary (#10 — the library's own guard is authoritative
and fires anyway; mirroring its `localize_naive` internals would be fragile
coupling), and the `**kwargs` half of the `call --param` structural-param gap
(no public method has `**kwargs`, so the guard already fails safe; the dict/JSON
half, the only reachable case, is fixed).

## Compatibility

Requires `libephemeris>=3.1.0,<4` and Python 3.12+, unchanged from a84. The
`[cli]` extra adds `typer>=0.26.4` (which vendors Click, so the CLI does not
depend on whichever `click` another dependency resolves) and `rich>=13.8.0`.
