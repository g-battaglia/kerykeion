# v6.0.0a56

This alpha rebases kerykeion on libephemeris 3 (`3.0.0a3`), the first major
release of the ephemeris backend. The dependency pin moves from `>=2.0.2,<3.0.0`
to `==3.0.0a3`. Two backend behaviour changes propagate into chart output, so
the affected report and SVG golden fixtures were regenerated.

## Backend handle renamed `swe` → `ephe`

The unified backend object exposed by `kerykeion.ephemeris_backend` is now
`ephe` (`from kerykeion.ephemeris_backend import ephe`). The old `swe` name is
removed with no alias: it implied Swiss Ephemeris is the engine, but
libephemeris is the primary backend and swisseph is a legacy fallback. Update
any `from kerykeion.ephemeris_backend import swe` import to `ephe`. The internal
helper `compute_sun_rise_set_swe` is likewise now `compute_sun_rise_set_ephe`.

## libephemeris 3 architecture

libephemeris 3 ships a four-backend architecture (Skyfield, the LEB fast path,
JPL Horizons and an adaptive `auto` mode) behind the same `calc_ut()` interface;
core planetary positions are unchanged within tolerance.

## Ephemeris output changes

- **White Moon / Selena repositioned.** libephemeris 3 computes Selena (body 56)
  on a ~7-year period (≈ `+0.1408°/d`) instead of the previous ~8.8-year period
  (≈ `+0.1120°/d`), shifting the point by up to a full sign in every chart that
  includes it. White Moon belongs to `ALL_ACTIVE_POINTS`, not the default point
  set, so default charts are unaffected; all-points reports and SVGs change its
  placement, distribution weight and aspect list.
- **Out-of-SPK-range bodies fall back to a Keplerian approximation.** For dates
  outside the SPK kernel coverage (≈ 1900–2100), asteroids and TNOs that were
  previously dropped now return a degraded two-body position (~1–2°) instead of
  raising, so historical and far-future all-points charts list more points (the
  1879 Einstein natal report grows from 45 to 53 active points).

## Security

`urllib3` is bumped to `2.7.0` (GHSA-qccp-gfcp-xxvc).
