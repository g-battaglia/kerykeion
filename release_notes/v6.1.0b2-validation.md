# 6.1.0b2 qualification

Qualified on macOS arm64 with the published `libephemeris==4.0.0b2`.
Both the library and CLI are `6.1.0b2`. No package upload was performed.
Machine-readable results: [v6.1.0b2-validation.json](v6.1.0b2-validation.json).
Final source identity and staged artifact hashes are recorded separately in
local release-preparation evidence; publication remains a maintainer action.

The union of passed case identities covers **all 14,663 unique collected test
cases**, not the sum of overlapping runs. There are no unverified case IDs.
The 13 medium-only skips are inappropriate for the extended kernel; all pass
in the separate medium profile. The remaining Python 3.12 skip requires the
optional Cairo system library; that test passes separately and in the strict
Python 3.14 complete run.

The full suites ran serially with indexed native readers, sealed native-network
policy and a 1 GiB process-tree RSS watchdog. Sampled peaks were 419.5 MiB for
Python 3.12 and 474.4 MiB for the strict Python 3.14 run. The medium subset peaked
at 108.5 MiB. GeoNames online tests are distinct from the sealed native ephemeris
policy and were exercised separately as well as in the Python 3.14 suite.

## Scientific continuity

- All five Libephemeris 4.0.0b2 registry SHA-256 values match the qualified
  upstream release files; none were yanked.
- Public b1/b2 source tags have identical `core`, `core/src` and `core/data`
  Git trees. Calculation bindings and runtime Python sources are unchanged.
- All 12 live extended-inventory inputs match the original model manifest's
  sizes and SHA-256 values, and report reviewed provenance.
- Original numeric and rendered references, producer attestations, coefficient
  files and numerical tolerances remain unchanged. The original manifest digest
  is `e05b99c22f03c24a49249d82ba82d3c8c929848d9e6dd8cb7dde738e04db9cd8`.
- Only 4.0.0b2 is explicitly qualified against the unchanged 4.0.0b1 reference
  model. Unknown/future versions still fail closed. The original producer
  generator remains pinned to its original engine rather than rewriting history.

This validates continuity within the v4 native model, not equality with v3 or
new scientific accuracy claims. See the [release notes](v6.1.0b2.md).

## Package qualification

Four artifacts (library/CLI, wheel/sdist) pass strict Twine metadata checks.
Both source archives rebuild into wheels whose complete member names and bytes
match the direct wheels. Every versioned runtime source/resource matches its
wheel member; license/NOTICE/font-license and generated man-page bytes are
checked. Private repository references and workspace/test/cache contamination
are rejected by the local archive audit.

Fresh wheel and source-rebuilt installations pass on Python 3.12 and 3.14,
using the actual PyPI Libephemeris dependency. Each of the four combinations
checks library-only import isolation before installing the CLI, lazy optional
imports, exact versions, canonical v2 model identity and scoring, SVG generation
with sealed bundled base data and an empty home, dependency consistency, CLI
`--version`/`--help`, and `status --check`. A not-yet-created profile store is an
expected first-run informational warning, not a failed installation check.

Only the four new qualified files belong in the root `dist/`; previous files
are retained outside it. See [manual publication](v6.1.0b2-publication.md).
