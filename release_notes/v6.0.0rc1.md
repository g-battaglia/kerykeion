# Kerykeion 6.0.0rc1

Release date: 2026-09-07 · First release candidate for v6 · Python 3.12+

Kerykeion 6 is ready for release-candidate testing. This release brings the v6
factory API, expanded calculation modules, modern SVG charts and the standalone
CLI into one versioned candidate. Both distributions use `6.0.0rc1`:
`kerykeion` is the library, and `kerykeion-cli` owns the `kerykeion` command and
depends on that exact library version.

## Install the candidate

```bash
# Library:
pip install --upgrade "kerykeion==6.0.0rc1"

# Library and CLI:
pip install --upgrade --pre "kerykeion[cli]==6.0.0rc1"

# Standalone CLI tool:
uv tool install --prerelease=allow "kerykeion-cli==6.0.0rc1"

# All optional extras, including Swiss Ephemeris and the CLI:
pip install --upgrade --pre "kerykeion[all]==6.0.0rc1"
```

An unqualified `pip install kerykeion` selects the stable release. The explicit
version selects this RC; `--pre` also admits the separate CLI prerelease when
installing it through an extra. The default backend remains pinned to
`libephemeris==3.2.1`.

## What v6 brings

- Factory methods returning Pydantic models, with a separate chart-data and
  SVG-rendering pipeline, JSON exports, text reports and XML context for AI
  consumers.
- Modern and classic chart styles, configurable themes, glyph sizes, optional
  chart marks and ten chart languages.
- Predictive and traditional techniques: primary directions, secondary
  progressions, solar arc, midpoints, astrocartography, profections, firdaria,
  zodiacal releasing, receptions and horary indicators.
- Range queries for lunations, ingresses, stations, sign periods and retrograde
  periods; transit samples can optionally carry their full subject and dignities.
- An argparse CLI in its own distribution, with saved subject profiles,
  structured output, warning envelopes and a typed public-factory dispatcher.

The [changelog](../CHANGELOG.md) records the complete alpha history. The
[migration guide](../site/docs/migration.md) covers API and result changes.

## Fixes since 6.0.0a93

- Solar arc directed points carry their directed speed (degrees per real-time
  day), consistent retrograde flags and no inherited natal motion classification.
- Count-limited heliacal searches stop after the final requested event, avoiding
  an unnecessary lookup beyond the search result or ephemeris boundary.
- CLI sequence parameters accept typed JSON arrays for nested data and model
  lists. CSV remains supported for scalar lists, including literal values
  beginning with `[` that are not valid JSON. Invalid structured input exits 4.
- The ancient-Rome report fixture now reflects the pinned backend's coverage:
  interpolated Lilith and perigee are omitted at year 100, with structured
  warnings, because the fitted apsides model does not cover that epoch.
- Installation, migration, dependency-policy text and agent guides now identify
  the RC consistently. The previously undated changelog entry is recorded as
  `6.0.0a93` (published 2026-09-05).
- Backend-specific tests now distinguish rendered geometry from reference
  coordinates and account for unavailable optional bodies. CLI tests isolate
  their stdout capture from pytest's live logging; payload assertions read
  stdout separately from diagnostics. These are test corrections, with no
  runtime calculation or rendering changes in the RC preparation.

## Upgrading from v4/v5

Python 3.12+ is required. The v4 compatibility layer and deprecated v5 aliases
are removed; use the factories and `kerykeion.schemas`. Direct module imports
may need updating even when a top-level factory import still works.

Review your expected results as well as imports: v6 changes the default active
points (18 to 14), natal and predictive orbs, luminary orb bonuses, the default
chart style, lunar-phase labels and tropical-chart nakshatra handling. Timezones
use `zoneinfo` and `tzdata`; the documented `is_dst` choice selects an offset.
See the [migration guide](../site/docs/migration.md) for exact mappings and
options for retaining earlier defaults.

A plain library install provides no shell command. Install the `cli` extra or
`kerykeion-cli`; use `python -m kerykeion_cli` instead of the former alpha
entry point `python -m kerykeion`.

## Known limitations

- The default base data covers 1850–2150, with the upper bound exclusive. Wider
  dates require a downloaded medium or extended tier. Individual optional
  bodies can have narrower coverage even with the extended tier; inspect
  `ephemeris_warnings` and point provenance. `source="Keplerian"` denotes an
  approximation, not ephemeris-grade precision.
- With every optional mark enabled, French and Italian biwheel side tables can
  overlap at long labels. The suite tracks these two cases as expected failures.
- Polar house-system substitutions and the reference backend's polar quadrant
  conventions remain documented behavior; review fallback metadata when
  working at extreme latitudes.
- The optional Swiss Ephemeris backend needs its own data files for full
  coverage. See [configuration](../site/docs/swisseph_configuration.md).

## Maintainer publication checklist

Artifacts are prepared in `dist/6.0.0rc1/`: one wheel and one source archive for
each distribution. Older files in `dist/` belong to earlier releases.

1. Review the prepared release commit and local tag `v6.0.0rc1`. Publish the
   commit and tag to the repository when ready. If creating a GitHub release,
   use this document as its notes and mark it as a **pre-release**.
2. Publish the library wheel and source archive:

   ```bash
   uv publish dist/6.0.0rc1/kerykeion-6.0.0rc1-py3-none-any.whl dist/6.0.0rc1/kerykeion-6.0.0rc1.tar.gz
   ```

3. Once the library is visible on PyPI, publish the CLI wheel and source archive:

   ```bash
   uv publish dist/6.0.0rc1/kerykeion_cli-6.0.0rc1-py3-none-any.whl dist/6.0.0rc1/kerykeion_cli-6.0.0rc1.tar.gz
   ```

4. Verify installation from PyPI in a fresh environment:

   ```bash
   uv run --isolated --no-project --prerelease=allow --with "kerykeion[cli]==6.0.0rc1" kerykeion --version
   uv run --isolated --no-project --prerelease=allow --with "kerykeion[cli]==6.0.0rc1" kerykeion status --check -f json
   ```

Release preparation creates the commit and tag locally. It does not publish
packages, create a GitHub release or push a tag. PyPI publication is the
maintainer's final step.
