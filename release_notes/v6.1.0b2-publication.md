# Publish 6.1.0b2

The `release/6.1.0b2` checkout is the candidate publication source. Once release
preparation finishes, its root `dist/` contains only these four qualified files:

- `kerykeion-6.1.0b2-py3-none-any.whl`
- `kerykeion-6.1.0b2.tar.gz`
- `kerykeion_cli-6.1.0b2-py3-none-any.whl`
- `kerykeion_cli-6.1.0b2.tar.gz`

From that checkout, with the publisher's local PyPI authentication available:

```sh
uv publish
```

This publishes the library and CLI distributions. The CLI pins
`kerykeion==6.1.0b2`; the library pins the already-published
`libephemeris==4.0.0b2`. Publication is a separate explicit maintainer action:
preparation, source commits/tags and dry runs do not upload package files.

The [qualification report](v6.1.0b2-validation.md) identifies the executed
matrix and scope. Final package hashes and the source commit are retained in
the local preparation evidence under `build/`; every staged file must match
those hashes. Old package files are kept outside `dist/`.

If an upload is partial, retain the same four files and resume publication;
never rebuild or replace a file name already uploaded to PyPI. Choose a new
version for any subsequent correction, and never move a frozen release tag.
