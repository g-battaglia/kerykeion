# Kerykeion 6.0.0

Release date: 2026-09-14 · First stable v6 release · Python 3.12+

Kerykeion 6 is the largest release in the project's history. It brings the
factory-based API, expanded calculation modules, modern and classic SVG charts,
typed serializable results, AI-ready context and the standalone CLI together in
a stable release. Both distributions use `6.0.0`: `kerykeion` is the library,
and `kerykeion-cli` owns the `kerykeion` command and depends on that exact
library version.

## Install

```bash
# Library:
pip install --upgrade "kerykeion==6.0.0"

# Library and CLI:
pip install --upgrade "kerykeion[cli]==6.0.0"

# Standalone CLI tool:
uv tool install "kerykeion-cli==6.0.0"

# All optional extras, including Swiss Ephemeris and the CLI:
pip install --upgrade "kerykeion[all]==6.0.0"
```

The default backend is pinned to `libephemeris==3.2.1`.

## Highlights

- Factory methods return typed Pydantic models, with separate chart-data and
  SVG-rendering stages, JSON exports, text reports and XML context for AI
  consumers.
- Modern and classic chart styles support configurable themes, glyph sizes,
  optional chart marks and ten chart languages.
- Predictive and traditional techniques include primary directions, secondary
  progressions, solar arc, midpoints, astrocartography, profections, firdaria,
  zodiacal releasing, receptions and horary indicators.
- Range queries cover lunations, ingresses, stations, sign periods and
  retrograde periods. Transit samples can optionally carry their full subject
  and dignities.
- The `kerykeion-cli` distribution exposes charts, techniques, sky events,
  profiles and the guarded public-factory dispatcher from the terminal. Its
  generated `kerykeion(1)` man page ships in the wheel.
- The repository includes agent skills for both the Python API and CLI, kept in
  sync with the public v6 surface by executable documentation gates.

The [changelog](../CHANGELOG.md) records the complete v6 development history.
The [migration guide](../site/docs/migration.md) covers API and result changes.

## Changes since 6.0.0rc1

- Relocated sidereal charts compute their house ring in the subject's configured
  frame, preserving Whole Sign and fixed-reference-frame cusp construction and
  planet houses at the birthplace.
- Topocentric Solar and Lunar return searches use the return location and
  altitude, matching the observer used to cast the returned subject.
- Historical ephemeris series and single subjects share one synthetic-LMT
  policy, so the same wall time and longitude resolve to the same UTC instant.
- Localized biwheel point and house tables use measured content widths,
  eliminating the tracked French and Italian label overlaps.
- Base-tier tests skip only cases that require medium ephemeris data; medium and
  extended runs continue to execute them.
- The CLI wheel now includes a generated Unix man page. Its examples, roff
  comments, package metadata and isolated-install smoke checks are validated by
  the release gates.
- Package metadata, installation instructions, chart assets and agent-skill
  instructions now use the stable version and canonical `main` branch.
- Online GeoNames examples are explicitly excluded from the offline documentation
  snippet gate, so release validation no longer depends on the shared API quota.

## Upgrading from v4 or v5

Python 3.12+ is required. The v4 compatibility layer and deprecated v5 aliases
are removed; use the factories and `kerykeion.schemas`. Direct module imports
may need updating even when a top-level factory import still works.

Review expected results as well as imports: v6 changes the default active points
(18 to 14), natal and predictive orbs, luminary orb bonuses, the default chart
style, lunar-phase labels and tropical-chart nakshatra handling. Timezones use
`zoneinfo` and `tzdata`; the documented `is_dst` choice selects an offset. See
the [migration guide](../site/docs/migration.md) for exact mappings and options
for retaining earlier defaults.

A plain library install provides no shell command. Install the `cli` extra or
`kerykeion-cli`; use `python -m kerykeion_cli` instead of the former alpha entry
point `python -m kerykeion`.

## Known limitations

- The default base data covers 1850–2150, with the upper bound exclusive. Wider
  dates require a downloaded medium or extended tier. Individual optional
  bodies can have narrower coverage even with the extended tier; inspect
  `ephemeris_warnings` and point provenance. `source="Keplerian"` denotes an
  approximation, not ephemeris-grade precision.
- Polar house-system substitutions and the reference backend's polar quadrant
  conventions remain documented behavior; review fallback metadata when
  working at extreme latitudes.
- The optional Swiss Ephemeris backend needs its own data files for full
  coverage. See [configuration](../site/docs/swisseph_configuration.md).

## Maintainer publication checklist

Artifacts are prepared in `dist/6.0.0/`: one wheel and one source archive for
each distribution. Older files elsewhere in `dist/` belong to earlier
releases.

1. Review the release commit and local tag `v6.0.0`. Push the commit and tag when
   ready. Use this document as the notes for a normal GitHub release, not a
   pre-release.
2. Publish the library wheel and source archive:

   ```bash
   uv publish dist/6.0.0/kerykeion-6.0.0-py3-none-any.whl dist/6.0.0/kerykeion-6.0.0.tar.gz
   ```

3. Once the library is visible on PyPI, publish the CLI wheel and source
   archive:

   ```bash
   uv publish dist/6.0.0/kerykeion_cli-6.0.0-py3-none-any.whl dist/6.0.0/kerykeion_cli-6.0.0.tar.gz
   ```

4. Verify installation from PyPI in a fresh environment:

   ```bash
   uv run --isolated --no-project --with "kerykeion[cli]==6.0.0" kerykeion --version
   uv run --isolated --no-project --with "kerykeion[cli]==6.0.0" kerykeion status --check -f json
   ```

Release preparation does not publish packages or create a GitHub release. PyPI
publication remains the maintainer's final step.
