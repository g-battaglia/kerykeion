# Kerykeion 6.1.0b1

Prepared 2026-11-04 · Prerelease · Python 3.12+ · library and CLI released together.

Both distributions use `6.1.0b1`; the CLI depends on that exact library version.
This beta combines PRs #272–#275 with the previously qualified native backend.

## Highlights

- Opt in to `RelationshipScoreFactoryV2` or the pure `score_positions` API from
  `kerykeion.relationship_score.v2`. The fixed profile evaluates all nine
  luminary pairs and both Venus–Mars directions, applies the special-award and
  destiny-bonus precedence, and exposes physical/scoring geometry separately.
  Existing v1 scoring remains the default. Read the [v2 API and numerical
  policy](../site/docs/relationship_score_factory.md#opt-in-v2-since-61).
- Modern rendering avoids classic fragments it would discard; wheel-only and
  aspect-grid exports construct only the components they consume. Aspect,
  translation and astrocartography preparation are local to each operation.
- Test execution is serial by default. `poe test:bounded` uses indexed reads and
  a sampled process-tree RSS watchdog, addressing memory exhaustion from
  automatic pytest workers retaining separate native ephemeris images.

## Measured performance

Six paired comparisons on an Apple M5 Pro, Python 3.12.13, with identical
base-tier data and owned readers on both versions:

| Workload | Before | After | Time reduction |
|---|---:|---:|---:|
| Full modern natal pipeline | 2.791 ms | 2.186 ms | 21.7% |
| Modern natal SVG | 2.014 ms | 1.437 ms | 28.6% |
| Modern synastry SVG | 4.602 ms | 3.582 ms | 22.2% |
| Natal aspect grid | 0.927 ms | 0.125 ms | 86.5% |

Wall and CPU reductions agree for these workloads. These are warm local timings,
not a library-wide speedup or a peak-RAM saving. Minified natal SVG improves only
1.1%; subject creation has no claimed improvement. The [full report and raw
samples](../docs/performance/python-6.1.0b1.md) retain all 23 workloads and limits.

## Native backend and other changes

- Pin the published `libephemeris==4.0.0b1` from PyPI: the Rust engine replaces
  the Python calculation backend. No local checkout or Git override is required.
- Adapt native sessions, coverage/source records, fixed-star lookup and heliacal
  configuration. Retain legacy token cleanup for compatibility.
- Bound metadata-only coverage caching; invalidate it on file/provider changes
  and bypass virtual readers, uninventoried bodies and unserved epochs. No
  astronomical calculations are cached or substituted by this adapter.
- Correct glyph-playground activation and regenerate the CLI man page.
- Keep Skyfield and its reference data development-only. Plain runtime installs
  do not require Skyfield/JPLephem or import that calculation stack. NumPy remains
  a transitive dependency of LibEphemeris's array APIs, but is not loaded by a
  plain Kerykeion import.

## Scientific compatibility

The v4 sidereal/house model changes some historical angles, house cusps and
outputs derived from them. Do not expect ancient charts to reproduce v3 output
bit for bit. Separate, model-labelled references preserve the original 398
fixture files and all existing numerical tolerances. Independent orientation,
house-geometry and rate controls cover 38 non-polar subjects; these checks are
not a blanket accuracy certificate.

Fixed-star names beginning with digits also need an identity-aware comparison.
The native backend resolves exact catalog names before the numeric-index
fallback: `72Cyg` selects that star's own astrometry, not the catalog entry
selected by `72`. Legacy numeric-prefix resolutions are not preserved for an
exact catalog name. This can materially change coordinates, conjunctions and
the membership of fixed-star discovery results; it is not merely floating-point
drift. Compare the exact name with its catalog ID before accepting reference
output changes. Native regression tests cover this distinction across the
`fixstar`/`fixstar2` families.

The default bundled planetary core remains deliberately small. Additional
bodies and wider date ranges still require the appropriate public LEB2 data.
The optional alternate backend was not qualified for this beta.

## Installation after publication

```bash
pip install --pre "kerykeion==6.1.0b1"
pip install --pre "kerykeion[cli]==6.1.0b1"
```

See the [qualification report](v6.1.0b1-validation.md) for executed checks,
profile coverage, package checks and platform limits, and the
[publication instructions](v6.1.0b1-publication.md) for the prepared artifacts.
Preparing/pushing this branch does not publish either distribution.
