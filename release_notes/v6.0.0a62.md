# v6.0.0a62

This alpha lands the pre-6.0.0 zero-bug review campaign, headlined by rounds
26–35: ten further review rounds, each rotating a fresh runtime-reproduced lens.
Every finding was reproduced offline before fixing and is covered by a
regression test; the fixes are error-contract, validation and
display-consistency hardening with no change to any correct computed value.

## Error contracts at the ephemeris and date boundary

`from_iso_utc_time` wrapped a raw `OverflowError` / `OSError` for an instant near
`datetime.max`/`min` whose local wall time overflows during the UTC→local
conversion. The `PlanetaryReturnFactory` crossing searches
(`solcross_ut`/`mooncross_ut` and the sibling helio/node crossings, forward and
backward) leaked a raw `libephemeris` error when the search stepped off the
loaded ephemeris range, and `RelocatedChartFactory` leaked the same `astimezone`
overflow for an extended-kernel extreme-year subject. All are now normalized to
`KerykeionException`, like every sibling event factory.

## Year 0 / BCE calendrical and ISO

Year 0 (1 BCE) stored as the ISO-8601 unsigned `"0000"` crashed chart rendering
because two display helpers routed it to `datetime.fromisoformat` (min year 1);
both now take the manual branch. A BCE subject rendered the local ISO's LMT
offset at minute resolution while deriving the Julian Day from the exact offset,
so the two ISO fields disagreed by up to ~30 s; the offset is now quantized to
the whole second and rendered `+HH:MM:SS`.

## Serialization, display and input validation

The text and LLM-context serializers rendered a within-~0.005°-of-cusp position
as the impossible `"30.00"` / `"360.00"`; a shared `format_degrees_below_bound`
now clamps just below the cusp. `EclipseFactory.search_from_location` and
`OccultationFactory.search_local` accepted an impossible latitude (`|lat|>90`,
reachable via a lat/lng swap) and returned a bogus "visible" event; both now
`validate_latitude`, and occultation search is restricted to an occultable-body
allowlist so it no longer fabricates events for calculated points.

## Known limitations documented

The campaign also records the residual known limitations rather than papering
over them: the post-2037 frozen-offset DST behaviour (pytz transition tables),
the approximate converse primary directions, the BCE proleptic-Gregorian vs
Julian calendar split, backend-dependent intermediate house-cusp speeds and
heliacal event dates, and the Swiss-Ephemeris-convention polar quadrant-house MC
flip (confirmed upstream as intended parity, libephemeris#46). Lenses that ran
fully clean — algebraic/property invariants, aliasing, concurrency, resource
lifecycle, serialization round-trips and more — are recorded as covered with no
defect.
