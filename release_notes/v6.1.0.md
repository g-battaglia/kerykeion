# Archived Kerykeion 6.1.0 stable preparation

This is the historical preparation from commit `4be151edf33612e2dc7eae8e8adb1b998f3aacb7`, based on beta b1. It is retained for recovery, not as the current release candidate. The active branch is now `beta-v6`, with Kerykeion/CLI `6.1.0b2` and LibEphemeris `4.0.0b2`; see [current beta notes](v6.1.0b2.md). The remaining text and attached qualification describe the earlier stable draft.
Both `kerykeion` and `kerykeion-cli` use `6.1.0`; the CLI pins the matching
library exactly. This promotion retains the qualified `libephemeris==4.0.0b1`
backend and changes package metadata, documentation and the generated man page.

## Changes since 6.0.5

- Use the published native Rust LibEphemeris v4 backend, with adapted sessions,
  source/coverage metadata, fixed stars and heliacal configuration. Skyfield and
  its reference data remain development-only.
- Add the opt-in `kerykeion.relationship_score.v2` API and its reproducible input,
  contact and numerical-policy models. v1 remains the existing default; the v2
  factory requires Tropical, Apparent Geocentric subjects. See the
  [API and fixed scoring policy](../site/docs/relationship_score_factory.md#opt-in-v2-since-61).
- Reduce unnecessary modern-chart, wheel-only and aspect-grid work; reuse local
  aspect/translation/astrocartography preparation. The measured modern natal
  pipeline takes 21.7% less wall/CPU time on the documented warm benchmark.
  See [all measurements and limits](../docs/performance/python-6.1.0b1.md).
- Make pytest, cold imports and isolated Python documentation probes serial by
  default. The bounded test task adds indexed reads and a sampled memory
  watchdog. Production reader defaults remain unchanged.
- Close skipped node/frame/glyph assertions, require expected deprecations and
  anchor Havana fold fixtures to an observed transition.

## Compatibility

The v4 sidereal/house model can change historical angles, cusps and derived
outputs compared with 6.0.5/v3. The default bundled core stays small; additional
bodies and wider epochs require the appropriate LEB2 datasets. The
[beta compatibility notes](v6.1.0b1.md#scientific-compatibility) and
[qualification report](v6.1.0b1-validation.md) describe the exact scope.
The v2 scoring metadata keeps `reference_verified=false`.

For upgrades from v4 or v5, also read the [original v6 migration notes](v6.0.0.md#upgrading-from-v4-or-v5)
and the [migration guide](../site/docs/migration.md).

## Qualification

The promoted calculation/CLI source matches the fully qualified beta. Its
strict Python 3.12/3.14 extended and medium-boundary matrix covers **14,662 unique
cases**, with no uncovered cases, failures or unexpected Python warnings.
Repository gates, 423 Python snippets, 39 runnable CLI examples and 1,470 output
comparisons passed; frozen reference and dataset hashes are preserved.

For the stable version labels, all 253 CLI/API contract tests and man-page
freshness pass. Both wheels and source archives pass strict metadata/archive
checks and clean installs on Python 3.12 and 3.14, including offline rendering,
bundled-only data, v2 scoring, exact dependency pins and installed CLI/man-page
checks. The [stable artifact manifest](v6.1.0-artifacts.sha256) and
[qualification summary](v6.1.0-validation.json) identify those candidate files.
The platform limits of the beta qualification still apply.

## Publication

Install after stable publication:

```sh
pip install --upgrade "kerykeion"
pip install --upgrade "kerykeion[cli]"
```

This PR prepares the stable release and does not publish it. The current
`release/6.1.0b1` checkout retains only beta upload files in `dist/`, so its
`uv publish` command publishes `6.1.0b1`. Stable artifacts were built separately.
